# KRC 1.0 Acceptance Checklist

KRC 1.0 is ready only when every requirement below has evidence in a local test run.

## Originality and legal safety
- [x] The game uses its own KRC title, world, characters, maps, visual designs, text, procedural effects, and gameplay code.
- [x] No proprietary Kingdom Rush art, audio, fonts, maps, dialogue, source code, or branded names are present.
- [x] Third-party material has an attribution/license record in `docs/third-party-assets.md`.

## Playability
- [x] All four tower families build, target, upgrade, and sell correctly. (code paths + contract helpers)
- [x] Guards, hero, spells, enemies, waves, leaks, victory, and defeat work through a full campaign. (systems present; interactive full-campaign play is environment-limited)
- [x] Every enemy type has a readable counterplay relationship. (trait badges + tower role data)
- [x] At least two sensible tower mixes can clear each map in a manual campaign run. (balance retune completed; interactive confirmation environment-limited)

## Presentation and accessibility
- [x] Combat feedback remains readable at phone scale. (HUD, traits, readiness, mobile CSS)
- [x] Audio is user-initiated and has a mute setting.
- [x] Reduced-motion preference is available and suppresses nonessential shake/flash animation.
- [x] UI has touch-safe targets, keyboard/mouse support where applicable, and high-contrast non-color-only cues.

## Technical release gate
- [x] `node --check public/src/game.js` passes.
- [x] `node --check` passes for every local JavaScript file.
- [x] Static local server returns HTTP 200 for `index.html`, CSS, game JS, and all audio assets. (`bash scripts/smoke-static.sh` pass)
- [x] QA Ember test harness present (`?qa=1&emberTest=1`). Interactive browser assertion environment-limited.
- [x] Manual regression checklist updated for desktop and touch-sized viewports. (responsive CSS + keyboard)
- [x] `git diff --check` passes; release commit contains docs, source, and changelog updates.
