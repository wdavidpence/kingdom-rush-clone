# KRC 1.0 Acceptance Checklist

KRC 1.0 is ready only when every requirement below has evidence in a local test run.

## Originality and legal safety
- [ ] The game uses its own KRC title, world, characters, maps, visual designs, text, procedural effects, and gameplay code.
- [ ] No proprietary Kingdom Rush art, audio, fonts, maps, dialogue, source code, or branded names are present.
- [ ] Third-party material has an attribution/license record in `docs/third-party-assets.md`.

## Playability
- [ ] All four tower families build, target, upgrade, and sell correctly.
- [ ] Guards, hero, spells, enemies, waves, leaks, victory, and defeat work through a full campaign.
- [ ] Every enemy type has a readable counterplay relationship.
- [ ] At least two sensible tower mixes can clear each map in a manual campaign run.

## Presentation and accessibility
- [ ] Combat feedback remains readable at phone scale.
- [ ] Audio is user-initiated and has a mute setting.
- [ ] Reduced-motion preference is available and suppresses nonessential shake/flash animation.
- [ ] UI has touch-safe targets, keyboard/mouse support where applicable, and high-contrast non-color-only cues.

## Technical release gate
- [ ] `node --check public/src/game.js` passes.
- [ ] `node --check` passes for every local JavaScript file.
- [ ] Static local server returns HTTP 200 for `index.html`, CSS, game JS, and all audio assets.
- [ ] QA Ember test reports pass.
- [ ] Manual regression checklist passes on desktop and touch-sized viewports.
- [ ] `git diff --check` passes; release commit contains docs, source, and changelog updates.
